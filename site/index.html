One core, two shells

The model is Clash for LLM privacy — borrow the architecture, not the brand. A mature Rust engine is the single source of truth; two delivery shells sit on top of the same policy semantics and label set.

Ctxward Core — Rust engine
detect · redact · tokenize · review · policy · audit · OPA strict-merge · session correlation · attachment scan · SSE

Desktop main line

Transparent take-over (Tauri shell): system proxy + local root CA, MITM only on whitelisted LLM SNIs. Single-user, single-machine. The open-source growth engine.

Gateway secondary

Explicit reverse proxy, headless, multi-tenant per-Bearer. Kubernetes / server. The enterprise monetization line.

What the engine already does

The data plane is production-ready and runs today as a reverse proxy (docker compose up).

  • Language-agnostic — apps stay unchanged, no SDK wrapper
  • Recursive scan — messages, JSON, SSE, multipart attachments
  • Five decisions — allow / redact / tokenize / review / block
  • OPA strict-merge — built-in policy first, strictest wins
  • Reversible tokens — AES-GCM-SIV, key from env, never disk
  • Review queue — 409 + ticket, replay after approval
  • Audit — hashes & labels only, never raw values
  • Observable — Prometheus, /readyz probe, /admin console
  • OOXML & PDF — node-level rewrite of docx/xlsx/pptx
  • Supply chain — cosign-signed images, CycloneDX SBOM

Ctxward is Apache-2.0-licensed and pre-1.0. The trust model for the desktop client is load-bearing: the root CA key is generated locally and never leaves the machine, MITM decryption is restricted to whitelisted LLM SNIs, and everything is open to audit. A privacy tool you can't inspect is just a backdoor.
